# Roadmap

Where each phase from the original plan landed, and what is deliberately next.

## Phase 1 — Core engine ✅

* Provider abstraction: `AnthropicProvider` (SDK or raw `httpx`) +
  `OpenAICompatProvider` (Ollama / Hermes / vLLM / OpenRouter / LM Studio), both normalizing to
  one `Completion` type — `nexus/providers.py`.
* Tool layer: file ops, shell, git, GitHub PR create/list/merge, plus memory and `ask_agent` —
  `nexus/tools.py`.
* Single-agent tool-calling loop with an approval gate — `nexus/agent.py`.

## Phase 2 — Auto role-routing ✅

* `roles.yaml`: role → keywords + persona + agent.
* `router.py`: weighted keyword fast-match → LLM classifier fallback (the exact roadmap prompt,
  chunked for a big team) → `general`.
* Every run auto-detects the role, switches the active agent and injects the persona; the switch
  is printed: `⇄ role: pentesting -> agent: openrouter-uncensored`.

## Phase 3 — 111 curated roles ✅ (963)

Shipped in `roles.yaml` (111 curated, generated and validated by `scripts/build_roles.py`)
plus 852 imported from five public repos under `roles.d/` (see [`docs/addagent.md`](addagent.md)):

| Source | Count |
| --- | --- |
| `roles.yaml` — curated core | 111 |
| `roles.d/agency-agents.yaml` | 283 |

Adding a role is a YAML block (or a dataclass entry in the generator) — no code change. Importing
a whole repo of them is `nexus addagent <url>` (one command, no code change). See
[`docs/roles.md`](roles.md) for every curated persona and [`docs/addagent.md`](addagent.md) for the
importer.

## Phase 4 — GitHub workflow polish ✅

* Auto branch naming: `feat/<role>-<short-task>` (slugified, collision-suffixed).
* Auto conventional-commit messages generated by `git_prepare` (`feat(backend): …` + changed-file
  body + role trailer).
* PR template auto-fill: `.github/PULL_REQUEST_TEMPLATE.md` placeholders replaced, plus a
  "Nexus run" footer with role → agent, branch, commits and diffstat.
* Optional auto-label and auto-request-review via `gh_create_pr` arguments.

## Phase 5 — VS Code integration ✅

* Tasks + debug configs (`.vscode/`) — worked from day one, terminal-based.
* Sidebar extension (`vscode-extension/`): activity-bar webview with live role/agent, an event
  log, and native **Approve / Approve & remember / Deny** — no terminal `y/N`.
* Built-in browser panel (`nexus panel`) sharing the same server and UI.
* GUI dashboard (`nexus gui` → `/dashboard`): live process timeline, cognition map, router prediction,
  token/telemetry meters, security audit log, in-page approvals, per-role memory.

## Phase 6 — Multi-agent collaboration ✅

* `ask_agent`: one specialist consults another mid-run (no tools, no recursion).
* Pipeline mode: `ship-feature`, `bug-hunt`, `security-review`, `content-drop`, `release` —
  sequential handoffs with the previous step's `finish` summary as the brief.

## Phase 7 — Memory & context per role ✅

* `.nexus/memory/<role>.md`, injected into that role's system prompt on every run.
* Written by the `remember` tool or `/remember`; capped by `settings.memory_max_chars`;
  disableable with `NEXUS_MEMORY=false`.

## Phase 8 — Model health & fallback ✅

* `fallback:` chain per agent, walked by `ProviderRegistry.call_with_fallback` with live events
  (e.g. Ollama down → Claude, with a warning).
* `nexus doctor`: checks every agent endpoint, pulled models, API keys, `gh`, git state, memory
  dir — `--json` for CI.

## Phase 9 — Self-learning (skills, memory, recall) ✅

Ported the mechanics that make Nous Research's
[`hermes-agent`](https://github.com/NousResearch/hermes-agent) improve with use:

* **Skills** (`nexus/skills.py`) — portable `SKILL.md` files discovered from the
  bundled `skills/`, `~/.config/nexus/skills/` and `<project>/.nexus/skills/`.
  The system prompt gets a compact index (≤60-char descriptions); bodies load on
  demand with `skill_view`. The agent writes them with `skill_manage`.
* **Memory** (`nexus/memory.py`) — `MEMORY.md` (facts, decisions) and `USER.md`
  (stable preferences) with hard caps, injected into every prompt.
* **Recall** (`nexus/sessions.py`) — every run lands in SQLite; FTS5 gives
  `/recall <query>` and the `recall` tool.
* **Learning loop** (`nexus/learning.py`) — after a non-trivial run a cheap model
  reviews the task, tool trail and result and may write one skill, one patch and
  up to three memory entries. `/learn` does it on demand; `skill_nudge_interval`
  reminds the model to save what it learned.
* **Curator** — stale skills are archived, never deleted.
* **GUI** — a LEARNING BRAIN card backed by `/api/brain`, `/api/skills`,
  `/api/recall`.

Full guide: [`docs/learning.md`](learning.md).

## Phase 10 — Hermes bridge + self-update ✅

* `nexus hermes status|install|sync|run` — shallow-clone upstream, import its
  200+ skills into Nexus, merge its `MEMORY.md`/`USER.md`, or hand a task to an
  installed `hermes` binary for the parts Nexus does not re-implement (gateway,
  TUI, terminal backends).
* `nexus update` — `git pull --ff-only` + reinstall from this checkout, with a
  clean refusal on a dirty tree.

## Deliberately not ported

Hermes' gateway (Telegram/Discord/Slack/…), its TUI, the Electron desktop app and
its remote terminal backends are separate products; Nexus keeps one interface
(CLI + GUI deck) and delegates when you need them (`nexus hermes run`).
